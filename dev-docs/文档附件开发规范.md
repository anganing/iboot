# 文档附件开发规范

本文用于 iboot 中任何"业务记录需要关联文档/图片/视频/图纸"的功能开发。已落地的参考实现是 MDM 的 ESOP 作业步骤附件（`mdm_route_op_esop` + `mdm_route_op_esop_file`），新功能一律沿用本文结构，不要各自发明。

## 1. 先定形态：单文件字段还是附件子表

| 场景 | 方案 |
| --- | --- |
| 一条业务记录最多只挂 1 个文件，且文件是该记录的属性（如营业执照扫描件） | 主表内联 `file_name`/`file_url`/`file_id` 三列 |
| 一条业务记录可能挂多个文件，或需要排序、逐个预览、区分文件类型 | **独立附件子表**，主表不放任何 `file_*` 列 |

判断标准只有一条：**业务上会不会出现第二个文件**。会，就直接上子表，不要先用单文件字段再返工——ESOP 就是因为一开始只留一组 `file_id`/`file_url`/`file_name`，实际要图 + 视频 + 图纸并存而被迫重构。

同时禁止把"内容形态"和"文件格式"混进一个枚举（曾经的 `doc_type` 同时塞 `TEXT`/`PARAM`/`IMAGE`/`VIDEO`/`PDF`）。正确做法是：业务文本、结构化参数各占独立字段，文件格式由附件子表的 `file_type` 表达。

## 2. 数据库设计

### 2.1 附件子表结构（固定模板）

表名 `<主表名>_file`，字段固定如下，不增不减：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint | 主键 |
| `<主表>_id` | bigint | 所属业务记录编号，非空 |
| `seq` | int | 附件展示顺序，非空，由后端按入参下标生成 |
| `file_type` | varchar(32) | `IMAGE`/`VIDEO`/`PDF`/`DRAWING`/`OFFICE`/`OTHER`，非空，**后端按扩展名判定** |
| `file_name` | varchar(255) | 原始文件名，非空 |
| `file_url` | varchar(512) | 文件地址，非空，**存去签名地址** |
| `file_id` | bigint | infra 文件编号，可空 |

外加项目标准审计字段 `creator`/`create_time`/`updater`/`update_time`/`deleted`。

索引：`idx_<主表>_file_<主表>_id (<主表>_id)`。附件表不需要唯一索引——同一记录挂两个同名文件是合法的。

主表侧需要给业务序号补唯一索引，例如 `uk_mdm_route_op_esop_route_op_seq_deleted (route_op_id, seq, deleted)`，避免同一父记录写入重复顺序。

### 2.2 字典

文件类型统一用 `<模块>_<业务>_file_type` 字典，6 条明细固定：

```
IMAGE 图片 / VIDEO 视频 / PDF PDF文件 / DRAWING 图纸 / OFFICE Office文档 / OTHER 其他
```

参考现有 `mdm_esop_file_type`。字典通过 DBX 写入 `system_dict_type` / `system_dict_data`，不写 SQL 脚本。

## 3. 后端实现

### 3.1 类结构

```text
controller/admin/<feature>/vo/
├── <Feature>SaveReqVO.java        # 含 List<<Feature>FileReqVO> files
├── <Feature>FileReqVO.java        # fileName/fileUrl 必填，fileId 可空
├── <Feature>RespVO.java           # 含 List<<Feature>FileRespVO> files + fileCount
└── <Feature>FileRespVO.java       # 全字段含 seq/fileType
dal/dataobject/<feature>/<Feature>FileDO.java
dal/mysql/<feature>/<Feature>FileMapper.java
```

`FileReqVO` 只收前端真正能提供的三个字段，`seq` 与 `file_type` **不允许前端传**：

```java
@Schema(description = "原始文件名", requiredMode = Schema.RequiredMode.REQUIRED, example = "绕线示意图.png")
@NotBlank(message = "文件名不能为空")
@Size(max = 255, message = "文件名长度不能超过 255")
private String fileName;
```

`SaveReqVO` 上必须有 `@Valid` 与数量上限，让校验落在框架层而不是业务代码：

```java
@Valid
@Size(max = 10, message = "附件数量不能超过 10 个")
private List<RouteOpEsopFileReqVO> files;
```

`FileMapper` 只需三个默认方法，全部走 `BaseMapperX`：`selectListByEsopId`、`selectListByEsopIds`、`deleteByEsopIds`。

### 3.2 Service 五条硬规则

参考 `iboot-module-mdm/.../service/esop/RouteOpEsopServiceImpl.java`。

1. **附件全量替换，不做逐行 diff**。create/update 都是先按父 ID `deleteByEsopIds` 再 `insertBatch`，`seq` 取入参下标 +1。逐行 diff 会导致顺序漂移，且代码复杂度换不来任何收益。

2. **`file_type` 在 Service 层按扩展名统一判定**，前端不传。映射表以静态 `Set<String>` 常量维护在 Service 内，前后端两处映射表必然漂移，所以只留后端这一处：

```java
private static final Set<String> IMAGE_EXTENSIONS = Set.of("jpg", "jpeg", "png", "gif", "bmp", "webp", "svg");
// ... VIDEO / DRAWING / OFFICE 同理，兜底返回 "OTHER"
```

3. **落库存去签名地址，读取时重新签发**。文件存储器签发的预签名 URL 24 小时过期，直接存库会让文档隔天打不开：

```java
// 写入
.fileUrl(HttpUtils.removeUrlQuery(file.getFileUrl()))
// 读取
file.setFileUrl(fileApi.presignGetUrl(file.getFileUrl(), null));
```

`HttpUtils.removeUrlQuery` 在 `iboot-framework/iboot-common`，`FileApi.presignGetUrl` 在 `iboot-module-infra`。

4. **"记录不能是空壳"的校验放 Service**，不放前端。业务文本、结构化参数、附件三者至少有一项，否则抛业务错误码（ESOP 用 `ROUTE_OP_ESOP_CONTENT_REQUIRED`）。前端 `ElMessage.warning` 拦不住直调接口。

5. **级联要覆盖三条路径**：
   - 删主记录 → 先 `deleteByEsopIds` 再删主行
   - 删父记录（如删工序、删整条路线）→ 先查出子记录 ID 集合，删附件、删子记录、删父记录
   - 复制父记录（如路线复制新版本）→ 复制业务记录时用 `Map<旧ID, 新ID>` 把附件的外键重指向新记录，参考 `RouteServiceImpl.copyRoute`

### 3.3 Mapper XML：一次 JOIN 出附件

详情查询用 `resultMap` + `<collection columnPrefix="f_">` 一次 JOIN，禁止应用层拼接：

```xml
<collection property="files" ofType="...FileRespVO" columnPrefix="f_">
    <id property="id" column="id"/>
    <result property="fileType" column="file_type"/>
    ...
</collection>
```

```sql
SELECT e.id, e.title, ...,
       f.id AS f_id, f.seq AS f_seq, f.file_type AS f_file_type, ...
FROM mdm_route_op_esop e
LEFT JOIN mdm_route_op_esop_file f ON f.esop_id = e.id AND f.deleted = 0
WHERE e.deleted = 0 AND e.id = #{id}
ORDER BY f.seq ASC
```

**列表分页不查附件明细，只用子查询带出数量**，避免分页记录数被 JOIN 放大：

```sql
(SELECT COUNT(1) FROM mdm_route_op_esop_file ef
 WHERE ef.esop_id = e.id AND ef.deleted = 0) AS file_count
```

## 4. 前端实现

### 4.1 上传字段组件

参考 `views/mdm/route/modules/route-op-esop-file-field.vue`。项目已有的 `components/upload/file-upload.vue` 只支持 `string | string[]` 形态的 URL 数组，拿不到原始文件名，所以多附件场景自建受控组件，`v-model` 绑定 `{ fileName, fileUrl, fileId }[]`。

要点：

- 上传走 `useUpload().httpRequest(file)`，它已封装前端直传 S3 与后端代理两种模式（由 `VITE_UPLOAD_TYPE` 决定），不要自己拼 `/infra/file/upload`
- **文件名直接取 `file.name`**，绝不从 URL 反解。URL 末段格式依赖存储器实现，反解出来的名字不可靠
- `accept` 用扩展名白名单常量拼 `.xxx,.yyy`，`beforeUpload` 里同时校验数量、扩展名、单文件大小
- 提供上移/下移调整顺序；`seq` 由后端按数组下标生成，前端只需保证数组顺序正确
- `watch(props.modelValue)` 回写时先比对内容是否一致再赋值，否则自身 `emit` 会触发回写抖动

默认上限 10 个 / 单个 50MB，工艺文档场景够用，不做可配置。

### 4.2 表单接入

附件字段直接作为 `useVbenForm` 的 `component`：

```ts
{
  fieldName: 'files',
  label: '附件',
  component: RouteOpEsopFileField,
  defaultValue: [],
}
```

提交前只回传后端 `ReqVO` 认识的三个字段，把回显带来的 `id`/`seq`/`fileType` 剥掉：

```ts
data.files = (data.files ?? []).map((file) => ({
  fileName: file.fileName,
  fileUrl: file.fileUrl,
  fileId: file.fileId,
}));
```

### 4.3 列表列

列表只显示附件数量，做成可点击的 `ElLink` 打开预览弹窗，数量为 0 时显示"无附件"文本，不要显示空白或 `0`。

### 4.4 预览

统一用 `@file-viewer/vue3` 的 `FileViewer`，渲染配置复用 `components/file-viewer/options.ts`（`fileViewerOptions` 已配好 CAD wasm、drawio、工具栏），不要各页面重复写一份 options。

多附件预览布局：左侧附件列表可切换，右侧渲染当前选中文件。

**取文件内容的方式按 URL 来源区分**，这是最容易踩的坑：

| URL 来源 | 取文件方式 | 原因 |
| --- | --- | --- |
| 后端返回的存储器预签名地址 | 原生 `fetch(url)` | 签名只覆盖 host，带上 `Authorization` 头会被存储器判定签名不匹配 |
| 后端代理下载接口 `/infra/file/{configId}/get/{path}` | `requestClient.download()` | 走项目请求链需要携带鉴权头 |

ESOP 附件属前者（`route-op-esop-preview.vue` 用 `fetch`），infra 文件管理属后者（`views/infra/file/modules/preview.vue` 用 `requestClient.download`）。

拿到 blob 后包成 `File` 交给 `FileViewer`，并用 `:key="\`${name}-${size}\`"` 强制切换文件时重建渲染器。

### 4.5 依赖前提

`@file-viewer/*` 已在 `pnpm-workspace.yaml` catalog 中声明，`apps/web-ele/vite.config.ts` 已挂 `fileViewerRenderers({ preset: 'all', copyAssets: true })`，渲染器静态资源产物清单是 `public/flyfish-viewer-assets.json`。新增预览页面不需要改这三处。

## 5. 验证清单

后端测试（继承 `BaseDbUnitTest`）必须覆盖：

1. 多附件保存后能按 `seq` 正确读回
2. 更新时旧附件被清理，不残留孤儿行
3. `file_type` 按扩展名判定正确（至少覆盖图片、视频、图纸、未知扩展名兜底）
4. 业务文本 / 参数 / 附件同时为空被拒
5. 删除业务记录时附件级联清理
6. 复制父记录时附件一并复制且外键重指向新记录

前端：

```powershell
npx vue-tsc --noEmit -p tsconfig.json
npx eslint --no-warn-ignored src/views/<module> src/api/<module>
```

页面手工验证：多文件上传、顺序调整、逐个删除、保存后回显、列表附件数、逐个预览（至少覆盖图片 + PDF + Office 三类）、跨天后重新打开仍可预览（验证重签名生效）。
