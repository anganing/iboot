### 1. disabled 按钮上的 tooltip 触发问题——已由主线程在共享组件修复（已解决，记录结论）

任务书要求 6「不可点的按钮保留展示并 `disabled` + `tooltip` 说明原因」。我按此把 7 个作业页
抽屉内所有状态禁用动作的 `disabled` 与 `tooltip` 收敛成同源的条件串：可用时给空串
（`TableAction` 对空串不渲染 ElTooltip），禁用时才给原因，避免可点按钮上挂着
"仅某状态可操作"的误导文案。

原先 `src/components/table-action/table-action.vue` 是 `<ElTooltip><ElButton disabled>` 直包，
而 `ElPopperTrigger` 用 `addEventListener` 把 mouseenter 等事件挂在 forwardRef 拿到的根元素
（即 `<button>` 本身，见 element-plus 2.14.2 `es/components/popper/src/trigger.vue` 的
`TRIGGER_ELE_EVENTS` 分支），浏览器对 `disabled` 的原生 `<button>` 不派发鼠标事件
（`ElButton` 用的是原生 `disabled` 属性而非 `pointer-events: none`），所以 tooltip 永不触发。

**主线程已在该组件修好**：对禁用按钮套一层 `.tooltip-anchor-disabled` span 承接悬停、
按钮本身 `pointer-events: none` 让指针穿透；`dropDownActions` 分支也补了 ElTooltip
（`ElDropdownItem` 是 `li`，只有 `cursor:not-allowed` 没有 `pointer-events:none`，悬停能命中，
不需要 span）。我负责的 7 个页面**无需任何配合改动**——页面里写的就是普通
`disabled: xxx !== ''` + `tooltip: xxx`，与新组件契约一致；我没有在任何页面自造 span wrapper。

补充现状（说明 tooltip 不是唯一的可读性来源）：`wms/workbench/pick`（`blockReason`）、
`wms/workbench/receive`（`truncated` / 待质检 / 上架结果三条 ElAlert）、
`wms/workbench/count`（差异与截断 ElAlert）、`mes/workbench/report`（状态 ElAlert）、
`mes/workbench/issue`（明细超限 ElAlert）、`mes/workbench/disposition`（未选处置单 ElAlert）
"为什么不能做"本来就用 ElAlert 摊在抽屉里。只有 `mes/workbench/inspect` 抽屉内没有 ElAlert，
原因当前只在 tooltip 里；该页主列表固定查 `status = 'CREATED'`，所以「开始检验 / 保存结果 /
提交结论」在该页永远是禁用态——这是 a27128a 之前就有的既有设计，不是本次改造引入，
我没有扩大范围去改它的作业范围。若要消掉这个永久禁用态，得改查询范围（属于业务口径，等老大定）。

### 5. 模板属性值内出现 ASCII 双引号会把属性截断（实施坑，建议进规范）

`disposition/index.vue` 我在 `:actions="[ ... ]"` 表达式内写了行注释，注释里带了 **ASCII 双引号**
`"列表有行却整列没按钮"`，eslint（vue-eslint-parser）报出一串误导性错误：
`missing-whitespace-between-attributes`、`unexpected-character-in-attribute-name`、
`Attribute 'onClick:' must be hyphenated`——属性值在第一个 ASCII 双引号处被截断，后面的内容被当成新属性名解析。

我用三个受控样本在仓库内跑 eslint 隔离验证过，结论明确：

| 注释里用的引号 | eslint 结果 |
| --- | --- |
| 无引号（`// 入口权限跟列表数据源对齐`） | 通过 |
| **ASCII 双引号**（`"列表有行却整列没按钮"`） | **报 8 条解析错误** |
| 全角引号（`“列表有行却整列没按钮”`） | 通过 |

所以触发字符是 **ASCII `"`**，不是全角引号（我最初猜反了，实测纠正）。
`vue/compiler-sfc` 自己的解析器三种都能过，只有 eslint 会拦——即 `pnpm build` 未必报错，
只有 lint 阶段暴露，容易漏。

处理：把这段说明移到标签外的 `<!-- -->` 里。**给后续 agent 的建议**：
模板属性值（`:actions` / `:title` 等）内的中文文案一律用「」角括号或全角引号，
不要用 ASCII `"` / `'`；这是字符串字面量边界，不是注释能豁免的。
本轮 7 个页面的 `@cell-click` 残留检查与 eslint 已全部通过
（`pnpm exec eslint src/views/mes/workbench src/views/wms/workbench` 退出码 0）。

### 2. `disabled` 按钮的 tooltip 触发问题——已由主线程在共享组件修复（已解决，记录结论）

`invlock` 解冻、`invreservation` 释放按规范 3.4 写了 `disabled` + `tooltip`。我复核 element-plus 2.14.2 源码确认了根因（与作业页组第 1 条同源）：`ElPopperTrigger` 经 `OnlyChild` 把 `mouseenter/mouseleave` 用 `addEventListener` 直接挂到 `<button>` 自身，`ElButton` 落的是原生 `disabled` 属性，浏览器不派发鼠标事件，所以 tooltip 永不触发。

**主线程已在 `src/components/table-action/table-action.vue` 修好**（`.tooltip-anchor-disabled` 外层 span 承接悬停 + 按钮 `pointer-events: none` 穿透；`dropDownActions` 分支补了 `ElTooltip`）。我这轮**没有**在任何页面自造 span wrapper，页面里就是普通 `disabled: !canUnlock(row.status)` + `tooltip: canUnlock(row.status) ? undefined : '原因'`，与新组件契约一致，修复自动生效，页面无需配合改动。

两个附带结论：
1. tooltip 可用时给 `undefined`（不是空串），`TableAction` 的 `v-if` 对 `undefined`/空串都不渲染 ElTooltip，避免可点按钮上挂"仅某状态可操作"的误导文案。
2. 我这几页 tooltip 文案里的枚举名用「」角括号而非全角引号，规避作业页组第 5 条记录的"模板属性值内弯引号被 HTML5 解析截断"问题（`vue/compiler-sfc` 与 eslint 在本文件实测均不报错，因为引号在 JS 字符串字面量内而非裸属性值，但按仓库统一口径仍改为「」）。

余额表 15 列达标，但列表字段全是**维度快照**（`matCode`/`matName`/`matSpec`/`lotNo`/`whName`/`locCode`/`uomCode`/`qualityStatus`/`stockScope`/`projectName`），没有任何 `xxxNo`。数据库侧 `uk_wms_inv_balance_dimension` 是 11 个 ID 列的联合唯一索引（组织+工厂+仓库+库位+物料+批次+容器+项目+项目任务+库存范围+质量状态），单列没有一个能定位本行。

代价：余额页成了三个账表页里唯一没有全字段入口的（`invtxn` 有 `txnNo`、`invlock` 有 `lockNo`、`invreservation` 有 `reservationNo`），`getInvBalance` 接口和 JOIN 字段是现成的，只差一个入口。两个选项请老大定：

1. 操作列加 1 个"详情"按钮（1 位 100），双击链路同 `invtxn`；代价是违背规范 7.1"账表只读页去掉行操作列"的字面表述——不过该条禁的是增删改，只读详情按钮不写入。
2. 给余额页顶部工具栏加一个"查看明细"提示，靠列表已有列拼出全貌，不做抽屉。

我倾向选项 1（余额是库存核对的第一入口，缺全字段视图最影响排障），但规范 7.1 的"去掉行操作"是硬约束、任务书也点名"账表只读别硬加操作列"，所以没自行加。

### 4. `invbalance` 的 `qtyAvailable` 是前端算出来的，详情抽屉无对应落库字段

列表用 `formatter` 现算 现存-预留-冻结。若第 3 条采纳选项 1，抽屉里这个字段同样只能前端算（后端 RespVO 没有 `qtyAvailable`）。已确认余额有乐观锁 `version` 字段，属对账信息，不建议展示给业务人员。

### 5. `devicetask` 的 B 入口是"看快照"，与编辑弹窗职责重叠但字段不重叠

设备任务有 `form.vue`（新增/修改），编辑弹窗覆盖可改字段；详情抽屉补的是列表和表单都没有的 `requestSnapshotJson`/`callbackSnapshotJson`/`sourceBizType`/`idempotencyKey`——设备对接排障唯一依据。按 Agent 作业规范"详情与编辑并存"处理，未把详情降级成编辑弹窗的只读态。若老大认为两个入口冗余，可以只留详情、把编辑收进"更多"。
