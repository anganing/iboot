# 后端支撑核查：检验方案抽屉与只读详情

## 结论：无需新增后端接口，但有一个必须避开的坑

### 1. 检验项目子表（任务 1）

`mes/qc-item` 六个接口齐全：`create` / `update` / `delete` / `delete-list` / `get` / `page` / `export-excel`。
`QcItemPageReqVO` 已带 `planId` 字段，`QcItemDO` 有 `planId`，前端按方案过滤可以直接 `getQcItemPage({ planId })`。

**坑：`planId` 在 PageReqVO 里不是 `@NotNull`。** 不传就返回全量，抽屉里会出现“没选方案却列出所有检验项”，批量删除也会跨方案误删。
处理：前端在 `planId` 为空时不发请求，返回 `{ list: [], total: 0 }`（与现有子表一致），不要为此改后端加 `@NotNull`——会破坏独立的分页查询语义。

子表表格内不显示 `planCode` / `planName` 两列（已在方案抽屉里，父标识进 `table-title`）。

### 2. 只读详情抽屉（任务 4）

各业务 `get` 接口均已存在（代码生成器直出），返回完整 RespVO，无需新增。

- 详情组件统一 `defineProps<{ id: string }>()` + `watch(props.id, load, { immediate: true })`，参照 `views/wms/countorder/count-order-process-detail.vue`。
- **必须处理 `get` 返回 null**：列表刷新后行被删，抽屉还开着，`get` 返回 null，直接取字段会白屏或抛错。取不到就展示空态，不抛错。
- 账表只读页（`wms/invbalance`、`wms/invtxn`）本身没有修改入口，双击详情是唯一看全字段的途径。它们的 `get` 接口按规范 7.1 应当只留查询：若发现还挂着 create/update/delete，本轮不动后端，只在文档记录。

### 3. 菜单与权限（任务 1）

`system_menu` 实测：

```text
2617 质量管理 (type=1, parent 2189)
  ├ 2247 质检任务      2275 检验项目   2282 检验方案
  ├ 2289 检验结果      2296 质检触发规则
2276~2280 = mes:qc-item:query/create/update/delete/export（parent 2275）
```

删除 `2275` 会让 `2276~2280` 变成孤儿权限项（父节点没了，角色授权树里挂不上）。
**决策：保留 2275 菜单行的权限项语义 —— 把 2276~2280 的 `parent_id` 改挂到 2282（检验方案）下**，再删除 2275。
这样 `mes:qc-item:*` 仍在授权树里可见，检验方案角色天然带上项目子表权限。
超级管理员角色已授 2275~2280（`system_role_menu` 各 1 条），改 parent 不影响已有授权记录。

## 4. 跨模块 JOIN 检查

`mes/qc-item` 的 `planCode`/`planName` 由模块内 JOIN 带出，符合规范；本轮不动。
