### 2.2 发现的问题

**问题：终态工序被当作"在制"锁定，既占求解资源队列又参与齐套扣料。** 2.1 快照里 DONE 工序 `locked_flag=1`——修正前 `MesOrderProjectionSource` 的逻辑是"只要不是 PENDING/READY 就打锁定标记"，DONE/SKIPPED/CANCELLED 也命中。连锁后果：

- `ApsSolverProblemBuilder#buildTasks` 会把已完工工序当 pinned 任务塞回资源队列，重新占用本轮产能；
- `ApsMaterialKitCalculator` 会跳过 lockedFlag 行不参与齐套——这一点对 DONE 无害（料已消耗完），但把"已完成工序"与"在制工序"混在一个标记里，语义上是错的。

### 2.3 修正内容（前任 AI 已落盘，本轮核验确认）

1. `iboot-module-aps/.../service/projection/source/MesOrderProjectionSource.java`：`lockedFlag` 改为 `!isNotStarted(status) && !isFinal(status)`——只有真正在制的工序（RUNNING/QC_WAITING）锁定在原资源；终态工序保留投影用于追溯但不再上锁。**只改 APS 侧投影逻辑，未改 MES 侧数据结构，未改投影表结构（无补列）。**
2. `iboot-module-aps/.../solver/ApsSolverProblemBuilder.java`：`buildTasks` 排除 `currentStatus` 为终态（DONE/SKIPPED/CANCELLED，走 `MesOpTaskStatusEnum.isFinal`）的投影行，不进求解域。
3. `iboot-module-aps/.../service/projection/kit/ApsMaterialKitCalculator.java`：需求分配同样跳过终态工序，双保险（即便历史投影行的锁定标记未刷新，终态也不会再占库存）。

配套测试改动：`ApsPinnedEndTimeTest` 的原"DONE 工序取实际完工时间"用例改写为 `shouldExcludeCompletedTaskFromSolverInput`（断言 803 不进 `solution.getTasks()`、804 进入且非 pinned）；`ApsMaterialKitCalculatorTest` 新增 `testFillMaterialShortage_skipsFinalTaskEvenWhenNotLocked`（DONE 且未锁定也不占料）。
