## 错误明细

| 页面 | 问题 | 复现步骤 | 当前表现 | 预期表现 | 处理状态 |
| --- | --- | --- | --- | --- | --- |
| `/wms/operation/count-order`、`/wms/workbench/count` 相关页面 | 控制台出现 `orderId` 类型不匹配警告 | 打开仓储相关页面并观察浏览器控制台 | `CountOrderLineList` 的 `orderId` 期望 Number，但收到 String，例如 `2098432401759043585`；同时出现 `Unhandled error during execution of component event handler` 和 `Object` 错误日志 | 前后端 ID 类型应保持一致，页面事件处理不应产生未处理错误 | 已修复（2026-09-12）：主键是雪花 ID，超出 JS 安全整数 2^53，后端 `NumberSerializer` 会把它下发成字符串，而子表 props 声明为 `number`。props 与 API 入参统一放宽为 `number \| string` 并原样透传（不做 Number()/parseInt，那会把 ...585 变成 ...600 的静默精度故障）。实测告警归零 |
| 全局菜单加载 | 菜单名称重复错误 | 进入仓储管理入口，观察浏览器控制台 | `menu name duplicate: 基础数据, id: 2610`；`menu name duplicate: 现场作业, id: 2675` | 菜单树名称或生成逻辑应避免重复错误 | 已修复（2026-09-12）：dbx 查证 2610=`/wms/basic`、2652=`/wms/workbench`、2675=`/mes/workbench`，是不同模块下的合法同名目录，不是脏数据，菜单表未改动；根因是目录型菜单 `component_name` 为空时前端退回用中文标题当路由名。已改为冲突时用唯一路径推导消歧 |
| 全局缓存初始化 | LocalStorage 前缀为空警告 | 进入仓储管理入口，观察浏览器控制台 | `[StorageManager] empty prefix combined with LocalStorageDriver`，提示 `clear()/keys()` 可能影响全部 localStorage | 应设置明确存储前缀，避免缓存清理影响其他本地存储项 | 已修复（2026-09-12）：不是环境变量未配，而是初始化时序——`PreferenceManager` 构造函数先 `new StorageManager()`（此时还没有 namespace，落到空前缀的 localStorage），namespace 要等 `initPreferences` 才注入并重建实例。构造期改用 `MemoryStorageDriver`，拿到前缀后仍走 localStorage，实测告警归零 |
