- 版本：v1.0.0
- 目标：五个检验点全部由规则自动生成任务，不存在判了报废但库存还在的状态，改检验流程只改规则数据不改代码。
- 依据：`dev-docs/业务流程/05-MES质量子域流程.md` 全文

- 前置：阶段 1 全部 31 个任务审查通过

## 阶段背景

质量子域的表结构、枚举、CRUD 全部就绪，但 `mes_qc_rule` 只有 CRUD 无触发解析逻辑，五检验点无法自动生成任务，处置单不联动库存与工序任务。

本阶段的核心是 `QcTriggerService`：一个方法把规则表变成活的。它建成后，五个检验点各自只是"在某个业务动作里调一次它"，代码量很小。

### T2-02 质检任务生成与抽样量计算

- 依赖：T2-01
- 依据：`05-MES质量子域流程.md` 的"规则解析"流程图后半段与"抽样与判定"的抽样方式表
- 独占文件：
  - 新增 `.../mes/service/qctask/MesQcTaskDomainService.java` 与 `Impl`（本任务只实现 `createQcTask`）
  - 新增 `.../mes/service/qctask/MesQcSampleCalculator.java`
  - 新增 `.../mes/service/qctask/bo/MesCreateQcTaskBO.java`
  - 新增对应测试类
- 做什么：
  1. `createQcTask(triggerPoint, QcTriggerContextBO)`：
     - 调 `QcTriggerService.resolve`，未命中直接返回空（业务动作放行）
     - 命中则建 `mes_qc_task`：`task_no` 走编码规则、`rule_id`、**锁 `qc_plan_id` 与 `qc_plan_version`**、`trigger_point`、`biz_type` `biz_no` `biz_line_id`、物料与批次快照、`qty` 送检数量、`status = CREATED`
     - 调 `MesQcSampleCalculator` 算 `sample_qty`
     - 按 `plan_id` 取 `mes_qc_item`（`status = 启用`，按 `sort_no` 排序），**为每个检验项 × 每个样本预生成 `mes_qc_result` 空行**（`sample_no` 从 1 到 `sample_qty`，快照 `item_code` `item_name`）
     - 幂等键落 `mes_qc_task.idempotency_key`，格式 `MES:{bizNo}:{bizLineId}:QC_CREATE:{triggerPoint}`；多行业务（如到货单多行）不能互相吞任务
  2. `MesQcSampleCalculator.calc(plan, qty)` 四种抽样：
     - `FULL`：返回 `qty`
     - `FIXED_QTY`：返回 `min(sample_value, qty)`
     - `PERCENT`：返回 `qty × sample_value ÷ 100` 向上取整
     - `AQL`：本轮简化，按 `acceptance_rule` 里配置的固定值取；未配置时退化为 `FULL`
  3. 预生成空行的数量上限：`sample_qty × 检验项数` 超过 500 时只按 `sample_no = 1` 生成一组（避免全检大批量时生成上万条空行），并在任务 `remark` 里标注。
  4. 测试：
     - 四种抽样方式各 1 个（`PERCENT` 用 `qty=105, sample_value=10` 断言 `sample_qty=11`）
     - 方案版本已锁
     - 检验项空行数量正确
     - 未命中规则返回空
     - 幂等重复调用不产生第二个任务
- 不做什么：
  - 不实现任务生命周期动作（T2-04）
  - 不实现结果录入（T2-05）
  - 不挂载业务动作（C 组）
- 验收：
  - 抽样计算测试通过
  - `mvn -pl iboot-module-mes -am test` 全绿
