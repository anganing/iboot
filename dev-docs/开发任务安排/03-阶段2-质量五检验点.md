# 03 阶段 2 质量五检验点与处置联动

- 版本：v1.0.0
- 目标：五个检验点全部由规则自动生成任务，不存在判了报废但库存还在的状态，改检验流程只改规则数据不改代码。
- 依据：`dev-docs/业务流程/05-MES质量子域流程.md` 全文
- 任务数：16
- 前置：阶段 1 全部 31 个任务审查通过

## 阶段背景

质量子域的表结构、枚举、CRUD 全部就绪，但 `mes_qc_rule` 只有 CRUD 无触发解析逻辑，五检验点无法自动生成任务，处置单不联动库存与工序任务。

本阶段的核心是 `QcTriggerService`：一个方法把规则表变成活的。它建成后，五个检验点各自只是"在某个业务动作里调一次它"，代码量很小。

  - 新增 `.../mes/service/qcrule/bo/QcTriggerContextBO.java`
  - 新增对应测试类
- 做什么：
  1. `QcTriggerContextBO` 承载业务对象的匹配维度：`objectType` `matId` `matCatId` `opId` `wcId` `supplierId` `bizType` `bizNo` `bizLineId` `batchId` `lotNo` `qty` `uomId`。
  2. `QcTriggerService.resolve(String triggerPoint, QcTriggerContextBO ctx)` 返回 `Optional<MesQcRuleDO>`：
     - 按 `trigger_point` 与 `status = 启用` 过滤规则（一次查询，结果可缓存在方法内）
     - 逐维度匹配：规则字段为 `0` 表示不限，非 `0` 时必须等于 `ctx` 的对应值（**与关系**）
     - `object_type` 必须匹配
     - 命中多条按 `priority` 降序取第一条；同优先级取 `id` 小的
     - 未命中返回空
  3. 匹配过程可解释：命中的 `rule_id` 由调用方记到 `mes_qc_task.rule_id`；未命中时打 debug 日志说明为什么（哪个维度没匹配上）。
  4. 校验规则引用的 `qc_plan_id` 对应方案 `status = PUBLISHED`，否则抛 `QC_PLAN_NOT_PUBLISHED`。
  5. 测试：
     - 单条不限维度规则命中
     - 多维度精确规则命中（`mat_cat_id` + `supplier_id`）
     - 多条命中按 `priority` 取高
     - 同优先级按 `id` 取小
     - 维度不匹配返回空
     - 引用未发布方案抛错
     - 停用规则不参与匹配
- 不做什么：
  - **不生成质检任务**（T2-02 负责任务生成，本任务只解析规则）
  - 不挂载到任何业务动作（C 组）
  - 不改 codegen `QcRuleService`
- 验收：

### T2-02 质检任务生成与抽样量计算

- 依赖：T2-01
- 依据：`05-MES质量子域流程.md` 的"规则解析"流程图后半段与"抽样与判定"的抽样方式表

  - 新增 `.../mes/service/qctask/bo/MesCreateQcTaskBO.java`
  - 新增对应测试类
- 做什么：
  1. `createQcTask(triggerPoint, QcTriggerContextBO)`：
     - 调 `QcTriggerService.resolve`，未命中直接返回空（业务动作放行）
     - 命中则建 `mes_qc_task`：`task_no` 走编码规则、`rule_id`、**锁 `qc_plan_id` 与 `qc_plan_version`**、`trigger_point`、`biz_type` `biz_no` `biz_line_id`、物料与批次快照、`qty` 送检数量、`status = CREATED`
     - 调 `MesQcSampleCalculator` 算 `sample_qty`
     - 按 `plan_id` 取 `mes_qc_item`（`status = 启用`，按 `sort_no` 排序），**为每个检验项 × 每个样本预生成 `mes_qc_result` 空行**（`sample_no` 从 1 到 `sample_qty`，快照 `item_code` `item_name`）
     - 幂等键落 `mes_qc_task.idempotency_key`，格式 `MES:{bizNo}:QC_CREATE:{triggerPoint}`
  2. `MesQcSampleCalculator.calc(plan, qty)` 四种抽样：
     - `FULL`：返回 `qty`
     - `FIXED_QTY`：返回 `min(sample_value, qty)`
     - `PERCENT`：返回 `qty × sample_value ÷ 100` 向上取整
     - `AQL`：本轮简化，按 `acceptance_rule` 里配置的固定值取；未配置时退化为 `FULL`
  3. 预生成空行的数量上限：`sample_qty × 检验项数` 超过 500 时只按 `sample_no = 1` 生成一组（避免全检大批量时生成上万条空行），并在任务 `remark` 里标注。
  4. 测试：
     - 四种抽样方式各 1 个（`PERCENT` 用 `qty=105, sample_value=10` 断言 `sample_qty=11`）
     - 方案版本已锁
     - 检验项空行数量正确
     - 未命中规则返回空
     - 幂等重复调用不产生第二个任务
- 不做什么：
  - 不实现任务生命周期动作（T2-04）
  - 不实现结果录入（T2-05）
  - 不挂载业务动作（C 组）
- 验收：
  - 抽样计算测试通过

### T2-05 检验结果录入与判定

- 依赖：T2-04
- 依据：`05-MES质量子域流程.md` 的"抽样与判定"判定链条图
- 独占文件：
  - 新增 `.../mes/service/qcresult/MesQcResultDomainService.java` 与 `Impl`
  - 新增 `.../mes/service/qcresult/MesQcItemJudge.java`（单项判定逻辑独立成类）
  - 新增 `.../mes/service/qcresult/bo/MesSaveQcResultBO.java`
  - 新增对应测试类
- 做什么：
  1. `batchSaveResult(MesSaveQcResultBO)`：批量保存实测值（一次提交多个检验项多个样本）。
     - 校验任务 `status = INSPECTING`
     - 逐条调 `MesQcItemJudge.judge` 判定，写 `actual_value` `pass_flag` `conclusion`（`PASS`/`FAIL`）`inspector_id` `inspect_time`
     - 全部 `required_flag = true` 的检验项都已录入时，任务自动推进 `INSPECTING` → `RESULT_POSTING`
  2. `MesQcItemJudge.judge(item, actualValue)` 按 `item_type` 判定：
     - `NUMERIC`：解析为 `BigDecimal`，判 `lower_limit <= 值 <= upper_limit`（上下限为空时该侧不限）
     - `TEXT`：与 `std_value` 字符串相等（去首尾空格）
     - `BOOLEAN`：与 `std_value` 相等（`true`/`false` 或 `1`/`0` 都接受）
     - 解析失败视为 `FAIL`，不抛异常
  3. `suggestConclusion(taskId)`：按 `acceptance_rule` 汇总建议结论，全部 `PASS` → `QUALIFIED`，有 `FAIL` → `REJECTED`。**这是建议，最终结论由人在 `submitConclusion` 时定**（可能选 `CONCESSION`）。
  4. 结果只在 `INSPECTING` 状态可改，`RESULT_POSTING` 之后不可改。
  5. 测试：
     - 三种 `item_type` 各 1 个通过 + 1 个超差
     - `NUMERIC` 只配上限、只配下限、都配的三种场景
     - 数值解析失败视为 FAIL
     - 全部必检项录完自动推进状态
     - 非必检项未录也能推进
     - `RESULT_POSTING` 后改结果抛错
- 不做什么：
  - 不做缺陷录入（T2-06）
  - 不做处置（T2-12）
- 验收：
  - 判定测试全部通过
  - `mvn -pl iboot-module-mes -am test` 全绿
