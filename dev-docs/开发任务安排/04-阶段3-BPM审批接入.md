# 04 阶段 3 BPM 审批接入

- 版本：v1.0.0
- 目标：五类高风险动作未经审批无法产生库存或工单事实，审批回调重复投递不产生第二笔过账。
- 依据：`dev-docs/业务流程/07-BPM审批接入流程.md` 全文；`dev-docs/BPM模块详细设计与接入规范.md`
- 任务数：9
- 前置：阶段 2 全部 16 个任务审查通过

## 阶段背景

全仓唯一已接入 BPM 的是 HRM 员工请假。`iboot-module-mes` 与 `iboot-module-wms` 的 pom 尚未引入 `iboot-module-bpm`。

本阶段的红线是**审批期间不改业务事实**：发起时业务单据进入审批中状态，审批通过的回调里才执行领域动作。阶段 1 与 2 在五个接入点都留了 `// TODO T3-xx` 注释，本阶段把它们换成真实的审批发起。

## 统一约定（红线）

| # | 约定 |
| --- | --- |
| 1 | 只走三个出口：`BpmProcessInstanceApi`、`BpmProcessTaskApi`、`BpmProcessInstanceStatusEventListener`。**禁止注入 bpm 内部 Service** |
| 2 | `form_type` 取 `CUSTOM`，业务数据存业务自己的表，**禁止用 `NORMAL` 埋进流程变量**（不可逆） |
| 3 | `approval_status` 复用 `BpmProcessInstanceStatusEnum`，**不自建枚举** |
| 4 | `businessKey` 传业务主键，发起流程与落单据同事务 |
| 5 | 审批期间不产生任何库存或工序事实 |
| 6 | 回调三层幂等：终态判定 + 实例编号与状态校验 + 带 `approval_status = RUNNING` 条件的 UPDATE |
| 7 | **`onEvent` 内不许抛异常**（跑在 Flowable 事务内，抛了会回滚流程状态变更） |
| 8 | 幂等键由 `businessKey` 派生 |
| 9 | 参照 `HrmAttendanceLeaveServiceImpl` 与 `HrmAttendanceLeaveStatusListener`。**模块内置的 OA 请假缺幂等保护，不要照抄** |

### T3-03 让步接收审批接入

- 依赖：T3-02
- 依据：`07-BPM审批接入流程.md` 的"让步接收"与"发起与回调范式"
- 独占文件：
  - `.../mes/service/disposition/MesDispositionDomainServiceImpl.java`（`submitDisposition` 的审批分支结构 + `updateConcessionApprovalStatus`）
  - 新增 `.../mes/service/disposition/listener/MesConcessionStatusListener.java`
  - 对应测试类
- 做什么：
  1. `submitDisposition` 在 `disposition_type` 为 `CONCESSION` 时：
     - 状态机 `DRAFT` 到 `SUBMITTED`
     - 调 `BpmProcessInstanceApi.createProcessInstance`，`processDefinitionKey` 取 `mes-concession`，`businessKey` 传处置单 id 的字符串
     - 同事务落 `approval_status = RUNNING` 与 `process_instance_id`
     - **不执行任何领域动作**
  2. **建立审批分支结构**：`submitDisposition` 里按 `disposition_type` 分派是否需要审批（本任务只实现 `CONCESSION` 分支，留好 `else if` 位置给 T3-04 的 `SCRAP`）。
  3. 新增 `MesConcessionStatusListener extends BpmProcessInstanceStatusEventListener`：
     - `getProcessDefinitionKey()` 返回 `mes-concession`
     - `onEvent` 转调 `updateConcessionApprovalStatus`，**内部 try-catch 全部异常并记日志，不向外抛**
  4. `updateConcessionApprovalStatus(businessKey, instanceId, status, reason)` 三层幂等：
     - 第一层：`BpmProcessInstanceStatusEnum.isProcessEndStatus(status)` 否则返回
     - 第二层：处置单的 `process_instance_id` 等于事件的实例编号，且 `approval_status` 为 `RUNNING`，否则返回
     - 第三层：带 `approval_status = RUNNING` 条件的 UPDATE，受影响行数不为 1 则返回
     - 通过后：`APPROVE` 置 `APPROVED` 并调 `executeDisposition`（`ConcessionHandler` 做质量状态过账）；`REJECT` 与 `CANCEL` 置回 `DRAFT` 并记 `approval_reason`
  5. 让步接收必须留存依据：`submitDisposition` 校验 `remark` 非空，否则抛 `DISPOSITION_CONCESSION_WITHOUT_REASON`。
  6. 删除 T2-12 留的 `// TODO T3-03` 注释。
  7. 测试：
     - 提交后审批中，库存分文未动（断言 `wms_inv_txn` 无新记录）
     - 审批通过后质量状态过账产生
     - 驳回后单据回 `DRAFT`，库存未动
     - **回调重复投递不产生第二笔过账**（连调两次回写方法）
     - `remark` 为空时提交抛错
- 不做什么：
  - 不改其他四个接入点
  - 不改 `ConcessionHandler` 的过账逻辑
- 验收：
  - "审批期间库存未动"与"重复回调不二次过账"两个断言通过
  - `mvn -pl iboot-module-wms,iboot-module-mes -am test` 全绿
