# 01 阶段 0 写入路径收口

- 版本：v1.0.0
- 目标：把 CRUD 界面从库存与工单的写入路径上撤下来，建立命令幂等载体。**不做这一步，后面全是白干。**
- 依据：`dev-docs/业务流程/03-WMS仓储库存流程.md` 全文，`04-MES生产执行流程.md` 的"一句话铁律"
- 任务数：20
- 完成标志：`rg` 搜不到任何 Controller 经 codegen Service 改库存余额或工单状态；每个领域动作都有幂等键；WMS 现有 21 个测试类全绿

## 阶段背景

WMS 是"先 codegen 生成 CRUD、再补领域层"的产物，18 张表有两套 DO 与两套 Service。领域层（过账、预留、冻结、四类单据）已完成且有测试，但 **Controller 全部注入的是 codegen Service**，界面上的每笔出入库都不改余额。

收口不是删掉一套。codegen 侧的 `selectPage` 与 Mapper XML 的 JOIN 查询有展示价值，保留；写入型方法删除，Controller 的写入端点转调领域 Service。

### 裁定一：单据明细行写入端点一律撤销，不做"仅 DRAFT 放行"

**背景**：T0-09/T0-11/T0-12/T0-10 四个任务条目写的是"明细行端点保持原样不动"，而 T0-13 条目写的是"明细行端点的写入改为仅在到货单 DRAFT 时放行"，两处口径不一致。四个执行 AI 都独立报了同一个问题并请求裁定。

**事实**：`/xxx-line/create|update|delete|delete-list` 走 codegen Service，**完全不校验主单状态**。已提交、甚至已过账的单据仍可经子表端点加行、改数量、删行。盘点单最严重——`book_qty` 是账实对比的基准，子表端点能直接改它、还能删掉不想盘的行，冻结后与差异确认后都拦不住。

**裁定：撤销这四个端点，只保留 `/xxx-line/page` 与 `/get`。** 理由：

1. 加 DRAFT 校验会形成两条写入路径（主单 `update` 整体替换 + 行级 CRUD），违反红线 1
2. 行级 CRUD 无法维护 `line_no` 连续性，也不重算单头汇总字段
3. 领域侧 `updateXxx` 的 `insertLines` 已是"旧行整批删除后重建"语义，DRAFT 态的明细编辑走主单 `update` 就够
4. 非 DRAFT 态的明细本就不该能改——那是流水已经记过的数据

**执行位置**：T0-17（它删 codegen 子表写入方法时一并撤端点）。调度方明确授权 T0-17 改这五个 Controller 的明细行端点段，这是本裁定的一部分，不算越界。

### 裁定二：codegen `BatchService.updateBatch` 作为例外保留

T0-16 的 `PUT /update-attr` 转调它，T0-17 若按"删所有写入方法"处理会让批属性维护编译不过。裁定保留，理由见 T0-16 自查的遗留 1：`wms_batch` 是主档表不是账表（账表只有余额、流水、预留、冻结四张），批属性是注册之后才知道的主数据补录、不改任何数量，与"账只能由领域动作改"不冲突；这与 T0-17 已写明的另一条例外（`wh` / `zone` / `loc` / `containertype` / `containermgr` 保留 codegen 写入）是同一类判断。T0-17 需在 `package-info.java` 的分工说明里把这条例外与理由写清。
