# 05 阶段 4 APS 进入执行闭环

- 版本：v1.0.0
- 目标：改一次工单交期，重排、发布、车间派工看到新计划，全链路无手工干预；缺料清单与齐套快照对得上。
- 依据：`dev-docs/业务流程/06-APS计划排程流程.md` 全文；`dev-docs/APS求解器开发规范.md`
- 任务数：4
- 前置：阶段 1 全部 31 个任务审查通过（本阶段可与阶段 2、3 并行）

## 阶段背景

APS 的场景、投影、求解、版本状态机、发布下达、缺料、负荷、任务锁定全链路已实现，测试 23 个类。剩下四件事：

1. 下达不推进 MES 工序任务状态，车间不知道计划已到
2. MES 执行闭环建成前投影里的工序进度全是初始值，重排会把在制工序当未开工
3. `aps_shortage` 与 `mes_kit_snapshot` 两套缺料数字并存，口径未对账
4. 部分代码风格违规

**不可协商的红线**（见 `APS求解器开发规范.md`）：Timefold 锁定 1.34.0；严禁出现 `moveThreadCount`、分区搜索、近邻选择、多阶段移动、约束剖析这些 Community 版会抛 `EnterpriseLicenseException` 的配置项；时间推导用声明式影子变量，不手写 `ListVariableListener`；约束名只在 `ApsConstraintNames` 里定义。

### T4-01 下达推进工序任务状态

- 状态：**已完成**

- 做什么：
  1. `applySchedule` 在更新 `res_id`、`planned_start_time`、`planned_end_time` 的同时，对当前状态为 `PENDING` 的任务把 `status` 推进到 `READY`（走 `MesOpTaskStateMachine`）。
  2. 已是 `READY` 的任务只更新计划时间与资源，状态不变。

  5. 返回的生效条数口径不变（实际更新的任务数）。
  6. 测试：
     - `PENDING` 任务下达后变 `READY` 且有流水
     - `READY` 任务下达后状态不变，计划时间已更新
     - `RUNNING` 任务被跳过（计划时间未变）
     - 重复下达同一版本不产生第二条流水

  - 不改 `ApsScheduleReleaseService` 的过滤与事务逻辑（除传 `versionNo`）
