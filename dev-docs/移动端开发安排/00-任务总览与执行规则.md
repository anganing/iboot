# 移动端开发安排 — 任务总览与执行规则

- 版本：v1.0.0
- 日期：2026-09-16
- 目标：把 `iboot-mobile` 从「只有移动审批与消息中心」推进到「车间/库房角色登录后工作台有真实可用的业务页面」。本版**不改后端**，全部复用 `/admin-api` 现成端点。
- 上游依据：`dev-docs/移动端接口契约.md`（T5-05）、`dev-docs/业务流程/01-总览与流程地图.md`、`iboot-ui/iboot-mobile/hermes/*.md`（移动端工程规范唯一事实源）
- 任务数：6（M0-M5）+ 1 个阻塞任务（M6 授权）
- 前置：后端 `iboot-server` 可启动、数据库 `ruoyi-vue-pro-20260817`（dbx 连接 `芋道-dev`）可用

## 一、为什么做这件事（背景）

`iboot-mobile` 现有 11 个页面，业务能力只到「BPM 移动审批 / 消息中心 / 动态工作台」这条**办公协同**线。而 `system_mobile_menu` 表里已预留四个坑位（生产报工、设备点检、库存查询、出入库作业），**全部指向 `/pages/placeholder/index` 占位页且 `status=0` 停用**。

配合 `MobileMenuServiceImpl.getMyMobileMenuTree` 的授权逻辑：超管走 `selectListByStatus` 全量分支，非超管按 `system_mobile_role_menu` 过滤。**结果是当前工作台对所有非超管用户是空的**——没有可分配的菜单。

本版的直接目标：把占位页换成真页面，让车间/库房角色登录后工作台有东西可用。

## 二、技术路线（两条硬事实决定，不接受"再评估"）

1. **`/app-api` 前缀本版复用不了。** `WebFrameworkUtils.java:114` 按 URL 前缀判定 `userType`（`/app-api` → MEMBER，其余 → ADMIN）。移动端登录复用 admin 体系、token 里 `userType=1`，业务请求打 `/app-api` 会被 `AccessDeniedException` 拒掉。
2. **移动端请求层 baseUrl 已含 `/admin-api`**（`env/.env:22` → `http://localhost:48080/admin-api`），`src/http/interceptor.ts` 直接 `baseUrl + options.url`，不做任何前缀剥离。

**所以：`src/api/*` 里写 `/wms/inv-balance/page`，实际打 `/admin-api/wms/inv-balance/page`。零后端改动。**

契约（`移动端接口契约.md`）定义的七个 `/app-api` 端点**不在本版范围**——它需要先解决 userType 判定、领域 BO 只收数字主键、`WmsSourceModuleEnum` / `MesSourceModuleEnum` 缺 `APP` 取值这三件事，是独立一件事，另立任务。

### 本版接受的一处取舍

`OpTaskController.fillCommand`（第 193 行）与 `ProdReportController.createProdReport`（第 73 行）把动作来源**写死 `MesSourceModuleEnum.UI.name()`**（WMS 侧同构）。

**后果**：移动端复用 admin 端点跑出来的动作，命令记录来源是 `UI` 不是 `APP`——功能完全可用，但事后**分不出「这条报工来自手机还是电脑」**。

**本版接受这一取舍**（避免扩大改动面），来源区分留作独立任务。任何任务不得为了"修正"这一点去改后端。

## 三、范围（含明确砍掉的部分，砍掉的理由必须站得住）

| 模块 | 本版接什么 | 砍掉什么 | 理由 |
| --- | --- | --- | --- |
| **WMS** | 库存查询（多条件 + 详情） | 出入库**动作** | 动作依赖角色授权 + 现场扫码，属第二批；只读查询立刻能用 |
| **MES** | 派工任务列表、工序任务详情、**报工提交** | 开工/完工动作 | 报工是"工位旁坐下来就能填"的真实移动场景；开工门禁五项在手机上不好解释 |
| **MES** | 批次追溯（正向/反向树） | — | "人不在电脑前但要立刻回答"的典型场景，纯只读、零风险 |
| **MDM** | ESOP 作业指导书查看 | 全部 28 项主数据维护 | 车间真有"看一眼图纸/视频"的需求；手机上改 BOM/工艺是自找麻烦 |
| **APS** | **一个都不接** | 全部 | 见下方展开 |

**APS 全砍的理由（不接受"加一个只读看板也好"）**：APS 的核心价值在「多方案对比 + 甘特拖拽调整」，这两个交互都依赖大屏横向视野与精细拖拽；手机能提供的只有"看某张工单被排到哪一天"，而这个信息通过 MES 工序任务的 `plannedStartTime` 已经能看到。**不接不是"来不及"，是"接了没人用"。**

3. `D:\iboot-pro\iboot\iboot-ui\iboot-mobile\hermes\conventions.md` — SFC 结构、TS 约定、UnoCSS
4. `D:\iboot-pro\iboot\iboot-ui\iboot-mobile\hermes\sop-new-page.md` — 新建页面三步、easycom、z-paging
5. `D:\iboot-pro\iboot\dev-docs\后台UI开发规范.md` — **注意：该文档面向 PC，其中 `useVbenVxeGrid`、`TableAction` 等红线不适用于移动端**。移动端用 `z-paging` + `wd-*`。文档中"禁止手写 el-table""操作列档位"等条款**不迁移**，但"列表状态必须映射中文""外键用选择器不暴露主键"这两条精神适用。

**移动端 UI 硬约束**：
- 一律用 wot-ui v2 的 `wd-*` 组件（区别于旧版 `wd-*` 的 `wd-design-uni`）；API 查询走 wot-ui MCP 工具或 `.claude/skills/wot-ui-v2/SKILL.md`
- 已知差异：按钮危险态 `type="danger"` 不是 `error`；`wd-picker` 的 `modelValue` 是数组
- **`wd-tag` 的 `type` 只吃固定枚举**：`default` / `primary` / `success` / `warning` / `danger` / `volcano` / `lightblue` / `cyan` / `pink` / `purple`。要自定义色用独立的 `color` / `bg-color` 属性，**不要往 `type` 里塞色值**（语义错乱且自带配色用不上）
- 列表页用 `z-paging`（easycom 已配置，`<z-paging>` 直接用），参考 `src/pages/notify/index.vue` 的 `queryList` + `completeByTotal` 写法
- 页面文件放 `src/pages/<模块>/<页面>.vue`，约定式路由**无需注册**，但必须写 `definePage({ style: { navigationBarTitleText: '...' } })`
- 禁止新增 `any`；API 响应类型必须在 `src/api/` 定义
- 主题色用 `text-primary` / `bg-primary`；安全区用 `p-safe` / `pt-safe` / `pb-safe`

**代码风格以移动端实际配置为准：单引号、2 空格缩进、行尾不加分号。**
- ⚠️ CLAUDE.md 里「加分号」那条是**面向 PC 端 web-ele** 的约定，**不适用于 `iboot-mobile`**。后者 eslint 走 `@uni-helper/eslint-config`（antfu 系，默认 `style/semi: never`），照 PC 端加分会直接让 `pnpm lint` 报错。参照 `src/utils/debounce.ts` 的实际写法。
- ⚠️ **`src/utils/index.ts` 不可被纯逻辑文件 import**：它顶层 `import { pages } from '@/pages.json'`，且内部调用 `uni.getAccountInfoSync()` / `getCurrentPages()` 等平台 API，**在 vitest 单测环境下加载即失败**。纯工具文件（如 `dict.ts`）必须零依赖自包含。

**验证的现实条件（重要，避免执行者浪费时间）**：
- **后端默认未启动**（48080 无监听），起服务还需 MySQL(3306) + Redis(6379)。**执行者不要尝试启后端、不要索要账号口令、不要改浏览器 localStorage 造登录态。**
- 所以**单个任务不要求端到端联调**：要求的是「代码正确 + 自己那部分门禁干净 + 如实声明未联调」。端到端联调由主线程（M6）在服务齐备时统一做。
- **严禁编造实测数字**。没联调就写「未做端到端联调（后端未启动）」，这不算失败，**编造才是**。
- 门禁命令 `lint`（裸 `eslint`，全仓库）与 `type-check`（全项目 `vue-tsc`）会被**并行任务**的半成品污染。处理方式：用 `npx eslint <自己的文件>` 自证自己那部分干净，全量命令照跑并把「被谁挡住」如实写进自查表。

## 六、状态标记规则

每份任务书末尾有状态表，两列含义不同，**不要混填**：

| 列 | 谁来填 | 允许的取值 | 什么时候填 |
| --- | --- | --- | --- |
| **自查状态** | **执行该任务的 subagent** | 完成 / 部分完成 / 未开始 / 阻塞 | 交付时如实填。**"部分完成"必须写清差什么；"阻塞"必须写清卡在哪、需要谁决策** |
| **审核状态** | **主线程（我）** | 待审查 / 通过 / 打回 / 通过（附条件） | subagent 交付后由我核对代码与实测结果填写 |

**填自查状态的纪律（照 `dev-docs/开发任务安排/` 的既有惯例）**：
- 只写**实际做到**的，不写"应该没问题"。没跑的命令不要写成跑过了。
- 实测数字要写出来（例如"库存列表返回 12 条，状态列显示中文"），不要写"验证通过"。
- 遇到的边界、未覆盖的场景、自己拿不准的地方**主动写进"遗留"**，不要藏。
- 审查发现的问题会被写进打回原因并要求返工——**如实填报比"一次通过"重要**。

### ⚠️ 当前验收标准（2026-09-16 修订，因工程基线问题临时降级）

原标准「三条全过」**当前不可能达成**，原因已查明并记入
[`08-附-工程治理任务（依赖版本与行尾与lint基线）.md`](./08-附-工程治理任务（依赖版本与行尾与lint基线）.md)：

- **`pnpm lint` 全仓 1327 errors**：根因是子项目 `.editorconfig` 要求 `end_of_line = lf`，而根目录 `* text=auto` + `core.autocrlf=true` 使工作区检出为 CRLF，与 prettier 默认 `lf` 冲突（1239 处 `Insert ␍`）。**配置自相矛盾，非环境脏。**
- **`pnpm type-check` 报 `node_modules/@wot-ui/ui/**` 内 TS2322**：根因是 `package.json:141` 把 `@wot-ui/ui` 写成 **`"latest"`**，装到 2.3.2，其 `open-type` 声明了 uni-app 类型定义尚不认识的 `getRealtimePhoneNumber`。**构建不可复现。**

**本轮任务的验收标准改为：**

| 项 | 要求 |
| --- | --- |
| `pnpm type-check` | **本仓库代码零错误**即可交付 |
| `node_modules/@wot-ui/**` 内的 TS2322 | **不算任务缺陷**，不要试图修（改 `node_modules` 无效、锁版本属依赖治理） |
| `pnpm test:run` | 必须全绿 |
| `npx eslint <你的文件>` | 必须 exit 0，这是 lint 的实际判据 |
| `pnpm lint` 全量 | 照跑，把结果与「被谁挡住」**如实写进遗留列** |
| 端到端联调 | 单任务**不要求**（后端默认未启动），由 M6 统一做 |

**严禁**为了「让门禁通过」而：改测试断言、删测试、`--fix` 全仓行尾、改 `node_modules`、改 `package.json` 依赖版本。这些都是越界，会被打回。

- **未跑的命令不要写成跑过了**；**未联调就写"未做端到端联调"**，这不算失败，**编造才算**。
- `pnpm lint` / `type-check` 是全项目命令，会被**并行任务**的半成品影响——用 `npx eslint <自己的文件>` 自证，并在遗留里说明被谁挡住。
