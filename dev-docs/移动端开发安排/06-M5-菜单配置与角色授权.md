## ⚠️⚠️ 重大订正：`status` 的语义是反的（2026-09-17，主线程）

**本任务书正文中所有"把 `status` 改为 `1` 以启用"的指示都是错的。实测事故已发生。**

芋道的 `CommonStatusEnum` 定义（`iboot-common/.../enums/CommonStatusEnum.java`）：

```java
ENABLE(0, "开启")     // 0 = 启用
DISABLE(1, "关闭")    // 1 = 停用
```

**`status=0` 才是启用，`status=1` 是停用。** 这与"1=true=开启"的直觉相反。

**铁证**：PC 端 `system_menu` 表里 **1044 条正常在用的菜单全是 `status=0`**，只有 5 条是 `status=1`（被禁用的）。

**已发生的事故**：M5 执行者照本任务书把 5 条移动端菜单的 `status` 改成 `1`，**等于全部禁用**。后端 `getMyMobileMenuTree` 的过滤条件是 `CommonStatusEnum.ENABLE.getStatus().equals(menu.getStatus())`（即 `status == 0`），结果超管登录后 `mobile-menu/my` 返回**空数组 `menus: []`**，工作台一片空白。

**主线程已修正**（dbx，2026-09-17）：
| 动作 | 菜单 |
| --- | --- |
| `status` 改为 `0`（启用） | `id=3 MES 作业`、`id=4 我的任务`、`id=6 WMS 作业`、`id=7 库存查询`、`id=9 批次追溯` |

| `status` 改为 `1`（停用） | `id=5 设备点检`、`id=8 出入库作业` —— 本版未实现的占位页，原为 `0`（启用）故一直显示 |

## 做什么

### 第一步：修正 `system_mobile_menu`（移动端菜单）

按新页面路径改写并启用：

| id | name | 新的 path | status |
| --- | --- | --- | --- |
| 3 | MES 作业 | （分组，path 空） | **1** |
| 6 | WMS 作业 | （分组，path 空） | **1** |
| 4 | 生产报工 → 改名「我的任务」 | `/pages/mes/task/index` | **1** |

> **订正（2026-09-16，主线程）**：本表原先写 `id=4` 改 `/pages/mes/task/report`，与下方正文要求的 `/pages/mes/task/index` 矛盾，是笔误。
> **正文为准**——报工页需要 `opTaskId` 参数，从工作台直接进会缺参打不开；工作台入口必须落在列表页「我的任务」，再由列表 → 详情 → 报工逐级进入。
> M5 执行者已按正文执行，判断正确。

**具体动作**：

1. **`id=6` WMS 作业分组启用**，其下 `id=7 库存查询` 的 path 改为 `/pages/wms/inv/index`，`status=1`
2. **`id=8 出入库作业` 保持停用**（本版不做 wms 动作，见总览范围）——**不要删**，留给第二批
3. **`id=3` MES 作业分组启用**，其下：
   - `id=4 生产报工` → path 改为 `/pages/mes/task/index`，`status=1`。**注意**：这个入口语义应改成「我的任务」而不是直接跳报工页（报工需要 `opTaskId` 参数，直接进会缺参），**建议把 name 一并改为「我的任务」**
   - **新增两个入口**：
     - 「批次追溯」→ path `/pages/mes/trace/index`，图标选合适的一个（参考现有 `tool` / `store` / `dashboard` 用法），`status=1`
     - 「作业指导书」**不单独挂菜单**（它必须从工序任务详情进，需要 `routeOpId` 参数）
4. **`id=2 消息中心` 和 `id=5 设备点检` 不动**（消息中心路径未变；设备点检本版不做）

**新增菜单的字段规范**（参考 `MobileMenuDO` 注释）：
- `type`：1=分组 / 2=入口 / 3=按钮权限码
- `path`：uni-app 页面路径，如 `/pages/wms/inv/index`
- `icon`：与现有行一致用图标名（`mail` / `tool` / `store` / `dashboard` / `settings`），**移动端 `work/index.vue` 的 `mapIcon()` 会做映射，未识别的图标回落 `apps`**
- `permission`：入口类型可留空（本版 app 页面不挂权限码，见契约 9.2 精神）
- 记得 `deleted=0`、`creator`/`updater` 等审计字段按现有行填

### 第二步：给车间角色分配 **PC 端权限码**（关键，页面的 403 就卡在这）

移动端页面调的是 `/admin-api` 端点，走的是**admin 的权限校验**。所以必须给角色分配 `system_role_menu`：

| 角色 | 需要分配的权限码 | 对应页面 |
| --- | --- | --- |
| 班组长 `mes_team_leader`(166) | `mes:op-task:query`、`mes:dispatch-task:query`、`mes:prod-report:create` | 我的任务、工序详情、报工 |
| 车间主管 `mes_workshop_leader`(170) | 同上 | 同上 |
| 仓储主管 `wms_warehouse_leader`(168) | `wms:inv-balance:query` | 库存查询 |
| 质量主管 `mes_quality_manager`(164) | `mes:trace:query` | 批次追溯 |
| 工艺工程师 `mes_process_engineer`(171) | `mes:op-task:query`、`mes:trace:query` | 工序详情、追溯 |

**做法**：从 `system_menu` 里查出上述 permission 对应的菜单 id（**这些菜单必须已存在**，是 PC 端已有的菜单），插入 `system_role_menu`。

查菜单 id 的参考 SQL：
```sql
SELECT id, name, permission FROM system_menu
WHERE deleted = 0 AND permission IN (
  'mes:op-task:query','mes:dispatch-task:query','mes:prod-report:create',
  'wms:inv-balance:query','mes:trace:query','mdm:esop:query'
);
```

⚠️ **`mdm:esop:query` 也要分配**（给班组长和工艺工程师），否则工序详情页里点「查看作业指导书」是 403。

### 第三步：给车间角色分配 **移动端菜单**（`system_mobile_role_menu`）

这是两个独立的授权体系，**别只做一个**：
- `system_role_menu` → 控制 `/admin-api` 权限码（决定接口能不能调）
- `system_mobile_role_menu` → 控制移动端工作台显示哪些入口（决定菜单看不看得见）

给 `mes_team_leader` / `mes_workshop_leader` 分配：MES 作业分组(id=3) + 我的任务 + 批次追溯
给 `wms_warehouse_leader` 分配：WMS 作业分组(id=6) + 库存查询
给 `mes_quality_manager` 分配：MES 作业分组 + 批次追溯

SELECT r.name AS role_name, m.permission
FROM system_role_menu rm
JOIN system_role r ON r.id = rm.role_id AND r.deleted = 0
JOIN system_menu m ON m.id = rm.menu_id AND m.deleted = 0
WHERE rm.deleted = 0 AND r.id IN (164, 166, 168, 170, 171)

JOIN system_mobile_menu mm ON mm.id = mrm.menu_id AND mm.deleted = 0
WHERE mrm.deleted = 0 AND r.id IN (164, 166, 168, 170, 171)
